# Smartika License Bot

> **EN:** A Telegram bot that sells software licence keys 24/7. Customers browse a
> catalogue, pay via YooKassa (card / SBP / B2B invoice), and activation codes are
> pulled from a 1C:Enterprise database over COM and delivered into the chat
> automatically. Built with Python and aiogram 3.

**Телеграм-бот для автоматической продажи электронных лицензий в режиме 24/7.**

## О проекте

Клиент выбирает лицензию в боте и оплачивает её картой или через СБП. Как только
ЮКасса подтверждает оплату, бот сам идёт в базу **1С:Управление нашей фирмой**,
забирает оттуда коды активации и отправляет их покупателю прямо в чат. Менеджеру
вмешиваться не нужно — продажа проходит полностью автоматически, в любое время
суток.

До этого коды выдавались вручную: клиент писал менеджеру, тот искал код в 1С и
пересылал его сообщением. Бот убирает человека из этой цепочки.

### Как это работает

```
Клиент выбрал товар  →  оплатил через ЮКассу
                     →  ЮКасса дёрнула webhook бота
                     →  бот запросил коды у 1С через COM
                     →  1С вернула коды активации
                     →  бот отправил их клиенту в чат
                     →  бот отчитался в группу менеджеров
```

## Возможности

**Магазин**
- Каталог из четырёх категорий: АТОЛ SIGMA, Frontol, ОФД (Такском / Платформа ОФД / OFD.ru), КриптоПро
- Выбор количества лицензий (1–10) с автоматическим пересчётом суммы
- Карточки товаров с изображениями и ссылками на тарифы производителя

**Оплата**
- Банковская карта и СБП через ЮКассу с генерацией ссылки на оплату
- Выставление счёта для юридических лиц: бот собирает реквизиты и передаёт менеджерам
- Произвольный способ оплаты — заявка уходит менеджеру
- Приём и обработка webhook-уведомлений от ЮКассы на собственном aiohttp-сервере

**Выдача товара**
- Автоматическое получение кодов активации из 1С УНФ через COM-соединение
- Тестовый режим без 1С (`ONEC_ENABLED=false`) — бот выдаёт коды `TEST-CODE-...`
- Хранение выданных кодов в личном кабинете покупателя
- Уведомление менеджеров об успешной выдаче и об ошибках, требующих ручной обработки

**Личный кабинет**
- История заказов
- Мои лицензии и коды — все купленные коды с датами
- Баланс
- Реферальная система с персональной ссылкой-приглашением

**Прочее**
- Заявка на обратный звонок (диалог через FSM: имя → телефон)
- Раздел «Оферта» с условиями возврата и «О нас»
- Уведомления менеджерам в рабочую группу Telegram

## Установка и запуск

### Что нужно заранее

- Python 3.9 или новее
- Токен бота от [@BotFather](https://t.me/BotFather)
- ID группы Telegram для уведомлений менеджерам
- _(для боевого режима)_ Windows-сервер с установленной файловой базой 1С:УНФ

### Шаг 1. Скачать код

```bash
git clone https://github.com/imrannasrullaev469-hue/smartika-bot.git
cd smartika-bot
```

### Шаг 2. Виртуальное окружение

```bash
python -m venv .venv
```

Активировать — Windows:

```bash
.venv\Scripts\activate
```

Активировать — Linux / macOS:

```bash
source .venv/bin/activate
```

### Шаг 3. Зависимости

```bash
pip install -r requirements.txt
```

### Шаг 4. Настроить .env

Скопировать шаблон — Windows:

```bash
copy .env.example .env
```

Скопировать шаблон — Linux / macOS:

```bash
cp .env.example .env
```

Затем открыть `.env` и заполнить значения (см. таблицу ниже). Минимум для
первого запуска — `BOT_TOKEN` и `GROUP_ID`; при `ONEC_ENABLED=false` бот
поднимется без 1С и будет выдавать тестовые коды.

### Шаг 5. Запуск

```bash
python main.py
```

В логах должно появиться `Бот запущен. Начало поллинга...` и
`Webhook-сервер запущен на порту 8080`.

### Шаг 6. Настроить 1С (только для боевого режима)

Отдельная пошаговая инструкция: [docs/1C_INTEGRATION.md](docs/1C_INTEGRATION.md).
Коротко: в 1С создаётся расширение конфигурации с общим модулем `bl_BotAPI`
и функцией `GetCodes(Product, OrderId, Quantity)`, у модуля ставится галка
«Внешнее соединение». После этого в `.env` выставляется `ONEC_ENABLED=true`.

### Установка на сервер без интернета

Если на сервере нет доступа в интернет, пакеты ставятся из заранее скачанных
`.whl`-файлов:

```bash
pip install --no-index --find-links=wheels -r requirements.txt
```

Сами wheels и установщик Python в репозиторий не входят (это ~39 МБ бинарников).
Собрать их на машине с интернетом можно так:

```bash
pip download -r requirements.txt -d wheels
```

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `BOT_TOKEN` | **да** | — | Токен Telegram-бота от @BotFather |
| `GROUP_ID` | **да** | — | ID группы менеджеров для уведомлений (отрицательное число) |
| `YUKASSA_SHOP_ID` | нет | пусто | ID магазина в ЮКассе |
| `YUKASSA_SECRET_KEY` | нет | пусто | Секретный ключ ЮКассы |
| `WEBHOOK_HOST` | нет | пусто | Публичный адрес сервера, напр. `https://shop.example.com` |
| `WEBHOOK_PATH` | нет | `/webhook/yukassa` | Путь, на который ЮКасса шлёт уведомления |
| `WEBHOOK_PORT` | нет | `8080` | Порт webhook-сервера |
| `ONEC_ENABLED` | нет | `false` | `true` — брать коды из 1С, `false` — выдавать тестовые |
| `ONEC_BASE_PATH` | если `ONEC_ENABLED=true` | пусто | Путь к каталогу файловой базы 1С |
| `ONEC_USERNAME` | нет | пусто | Пользователь **внутри 1С** (не учётка Windows) |
| `ONEC_PASSWORD` | нет | пусто | Пароль этого пользователя 1С |

## Технические заметки

Неочевидные вещи, о которые легко споткнуться при доработке.

**Импорт pywin32 только в главном потоке.** В `services/onec.py` модули
`pythoncom` и `win32com.client` импортируются на уровне модуля, а не внутри
функции. Это обязательное условие: первый импорт pywin32, выполненный внутри
рабочего потока asyncio, роняет весь процесс с access violation. Если перенести
импорт внутрь `_get_codes_sync`, бот будет падать при первой же продаже.

**COM синхронный.** Вызов 1С уходит в отдельный поток через `asyncio.to_thread`,
иначе он блокирует event loop и бот перестаёт отвечать всем остальным
пользователям на время запроса к базе.

**Соединение с SQLite защищено `Lock`.** Оно создаётся с
`check_same_thread=False`, потому что aiogram работает в нескольких потоках,
и без блокировки одновременные записи разошлись бы.

**Боевой код ЮКассы.** В `services/yukassa.py` сейчас заглушки. Рабочий шаблон
вызовов `Payment.create()`, `Payment.find_one()` и проверки подписи через
`hmac.compare_digest` лежит в истории git — в коммите
`feat: оплата через ЮКассу и webhook-сервер`. Посмотреть можно так:

```bash
git show fcf5e85:services/yukassa.py
```

**Формат ответа 1С.** Функция `bl_BotAPI.GetCodes` возвращает одну строку вида
`код1;код2;код3`, бот разбивает её по `;`. Если в 1С поменяется разделитель,
править нужно в `_get_codes_sync`.

## Известные проблемы

Зафиксированы для прозрачности, будут исправлены отдельными задачами:

| # | Проблема | Влияние |
|---|---|---|
| 1 | `utils.py` — `BASE_DIR` содержит зашитый абсолютный путь macOS (`/Users/...`) | На Windows-сервере не находятся изображения, меню молча уходит в текстовый фолбэк без фото |
| 2 | Проверка подписи webhook ЮКассы закомментирована, `verify_webhook_signature()` всегда возвращает `True` | В боевом режиме поддельный POST-запрос может спровоцировать бесплатную выдачу кодов. **Обязательно включить до приёма реальных платежей** |
| 3 | `keyboards/init.py` вместо `__init__.py` | Файл ни на что не влияет (работают namespace-пакеты), но вводит в заблуждение |
| 4 | Боевой код ЮКассы в `services/yukassa.py` закомментирован — используется заглушка | Реальные платежи не проводятся, пока не заполнены ключи и не раскомментирован код |
| 5 | `docs/1C_INTEGRATION.md` описывает вариант через HTTP-сервис | Реализация в итоге сделана через COM; инструкцию нужно актуализировать |
